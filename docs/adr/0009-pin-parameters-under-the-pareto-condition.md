# 帕累托极限下允许固定任一参数，其余求极限

[ADR 0008](0008-report-scenario-limits-as-a-pareto-point.md) 把场景速算的道路极限尺寸定为帕累托前沿上的一个点，并明确拒绝“锁定部分尺寸求其余”的开关：那会让“极限尺寸”在同一个界面里同时有全解与条件解两种含义，把好不容易消掉的歧义又放回去；需要固定某几项时改用反向校核。这一条在实际使用中站不住。前沿上的点本来就不唯一，需求方要的正是**在前沿上走** —— 主路已经定了 3.5 m，支路还能压到多窄；某条腿的偏移现场只允许 0.2 m，其余尺寸要多少。反向校核回答不了这些：它要求把每一项都填满，而使用者正是因为不知道其余几项才来算。于是需求方要求把影响帕累托点的每一个参数都交给用户调节，求解器只负责其余部分。

## 决定

**计算方向与工况合并为一组：道路中心线 / 帕累托极限。** 此前左栏有“求道路极限 / 校核给定道路”与“道路中心线 / 极限工况”两组控件，四个组合里只有两个真正不同：可偏离中心线与可固定参数总是一起出现，校核只是把参数全部固定的特例。道路中心线下全部横向偏移为零、道路尺寸全部由求解器给出，左栏只列给定项（U 型隔墙宽，后缀“（给定）”）；帕累托极限下车辆可偏离中心线，左栏列出该场景全部道路尺寸与全部腿的路径偏移（含 U 型起弯点）。变体总数仍为 24。

**固定参数（`Pins`）。** 帕累托极限下用户改过的尺寸或偏移即视为固定，行右侧的“固定”开关自动勾上；取消勾选即交回求解器。固定的按给定值参与求解，未固定的尺寸压到极限、未固定的偏移由求解器优化，两者都回填到输入框，因此输入框里永远是一组自洽的数。偏移输入允许超出可行区间的值，结果直接报越界而不拦截：用户固定一个偏移正是为了看它能不能行。

**校核并入固定。** 全部待求尺寸都被固定时无可求解（`solved_keys` 为空），结果为通过 / 临界 / 越界的判定，判定规则与既有越界分析同源。独立的“校核给定道路”计算方向与右栏“校核明细”卡随之移除 —— 单独保留一个入口只是同一件事的第二个名字。

**共用腿恒零、不可固定。** 双向布局里被两条镜像机动共用的腿（T 口支路、十字倒车道、借支路的支路、三巷的中巷）偏移固定为 0：两条机动互为镜像，任何非零偏移都只会让其中一条更紧，对称性已经替用户做了选择。该行照样列出，但置灰、显示 0、无开关。

**封顶规则。** ADR 0008 以中心线解逐项封住帕累托解的搜索上界，依据是“各腿偏移都可以取零，中心线解在其下必然可行”。有横向偏移被固定时这条依据失效 —— 车辆不再自由停在中心线上 —— 因此不施加封顶；只固定尺寸或起弯点时封顶照旧，被固定的项一并带进中心线求解。

**释放规则。** 切换场景、单/双向、档位或计算方向时释放全部固定：布局一变，固定的那个数就不再对应同一条腿。改车辆参数（转弯半径、车宽、中心前距、中心后距、净距阈值）保留固定，使用者正是要看同一条固定的路换车之后还行不行。

**顺带修正借支路的 `so` 符号。** 借支路场景的支路偏移此前与“弯道内侧为正”约定相反（`_stubback` 对 `so` 取了负）。参数未交给用户之前这只是内部约定，交给用户固定之后正负号就是界面语义的一部分，必须与其他腿一致。夹具 `tests/fixtures/scenario_clearance.json` 由旧符号的原型生成，夹具本身保留不改，加载时把 `so` 取反后再喂给 Python，逐位对拍不受影响。

## 后果

“校核给定道路”不再是独立入口。要校核一条既有的路，选帕累托极限、把全部尺寸填上即可；要校核车辆走中心线的情形，另把全部偏移固定为 0。

“道路极限尺寸”的含义由“全部待求尺寸的帕累托点”变为“在固定项周围的帕累托点”：固定项为空时两者相同。这正是 ADR 0008 担心的那个歧义，现在由界面消解 —— 结果卡仍写“一组最小可行尺寸（非唯一）”，固定的项在偏移卡里标“（固定）”，左栏的开关状态随时可见，使用者不会把条件解误读为全解。

固定横向偏移时可能解出比中心线更宽的路。这是用户主动固定的后果而非求解器失误：用户钉住的位置本就比中心线更费道宽，求解器如实回答。未固定横向偏移时“帕累托极限逐项不大于中心线解”的不变量依旧成立，仍固定在测试中。

原型 `design_handoff_scenario_calculator/` 的 UI 与求解层未同步这一变更，仅几何求值层继续用于对拍。
