# 通行余量以路径自身的横向偏置求解，转角半径为自由度的因变量

通行余量把偏置定义为“把一个区段的全部位姿沿行进方向的法向整体平移”，而不是“下发路径中心线相对某条车道走向线的横向差值”。既有模型里通行区域是全部启用车道区域的并集，路径不绑定到某一条车道；若为了给偏置一个参照物而引入持久的路径↔车道绑定，会为一个只读的辅助分析改动核心模型。以路径自身为参照后，可行偏置带的定义是自洽的：对该段做横向平移、重跑既有的扫掠判定链路、二分求出使最小净距等于阈值的边界。车道只在两处以**局部派生事实**的形式回来 —— 区段命名取覆盖该段中点的启用车道名，需求道宽三区标尺改写该车道的总宽后重建通行区域再二分；两者都是几何反查的结果，不产生任何持久绑定。

需求道宽因此没有闭式公式，全部由单调搜索得到。代价是一次三区标尺要重建十余次通行区域，约一秒；换来的是这个读数与界面上其他一切净距读数出自同一条链路，不会出现“公式说能过、扫掠说不能过”的分裂。

转角求解的三个自由度是入弯段偏置、出弯段偏置和起弯点。这三者只有在**路径转弯半径成为因变量**时才互相独立：两条腿的横向位置一旦定下，切于两腿且转角固定的圆弧构成一个单参数族，起弯点选的正是族中的哪一条。若同时把半径当作给定值，第三个自由度就不存在，或者圆弧末端落不到偏置后的出弯腿上、路径不再连续。据此实现后，推迟起弯收紧半径、提前起弯放大半径，而半径放大时扫掠带反而变窄 —— 这恰好是这套功能要讲清楚的那条反直觉结论，界面把本次解算出的半径与拟合得到的原半径并排显示。

转角求解作用在拟合出的直线—圆弧—直线参数化形式上，不是原始离散位姿序列；否则“车道倒角半径与路径转弯半径不等”这一整条主线没有载体。拟合残差随结果一并显示，不隐藏。

相邻两个转角之间的连接段只有一个偏置值，因此该段区间取前后两个转角要求的交集。交集为空时只报告冲突与差值，不求所需的半径调整量：逐转角独立求解会给出互相冲突的建议，售前照着改会发现改不动，比不给建议更糟；而把半径调整量也解出来属于另一批功能的范围。

求解结果全部是当次会话的派生结果，不落盘。既有本地存储只保存用户输入（连接配置、车道、半径测量），派生结果落盘会立刻带来“车道改了结果过期”的一致性负担，而这批功能只给建议、不写回下发路径也不修改车道，本来就不需要它。CSV 与 PDF 是仅有的出口。
