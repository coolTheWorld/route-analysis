# 架构说明

## 设计目标

核心几何和存储不依赖 Qt，使车辆/车道算法能够在无窗口环境中验证。UI 只编排查询、选择、编辑和呈现；后端差异集中在一个只读客户端，避免 HTTP 字段假设散落于组件。

## 模块边界

```text
app / main_window
├── settings_dialog ─────────────┐
├── api_client ── parsing        │
├── canvas / control_panel       │
│   ├── geometry                 │
│   ├── lane_generation          │
│   ├── turn_radius              │
│   ├── turn_measurements        │
│   └── radius_graphics          │
├── analysis ─── geometry        │
├── storage ──── models          │
├── logging_setup                │
└── workers                      │
                                ▼
                         runtime data/ + log/
```

- `models.py`：不可变路径姿态、车辆参数、分析结果，以及可编辑车道对象。
- `geometry.py`：车辆矩形、yaw 最短角插值、圆弧/贝塞尔离散与真实长度、车道变换、缓冲与多车道并集。
- `lane_generation.py`：路径去重/简化、尖角/真实圆弧/分段贝塞尔生成、偏差统计及相切圆弧半径编辑。
- `turn_radius.py`：转弯区间、累计 yaw、整弯等效旋转中心、前轴中心和四角固定半径。
- `turn_measurements.py`：自动/手动测量的名称、端点、计数器、路径指纹、重新计算和本地持久化。
- `radius_graphics.py`：已选测量的路径区间、端点车辆、等效圆心、五条半径线和五条圆弧轨迹。
- `analysis.py`：对路径做位置/yaw 双约束采样并输出净距与越界结果。
- `api_client.py`：唯一 HTTP 边界，只暴露必要查询；负责认证、单次重登、分页和响应校验。
- `parsing.py`：解析 `AgvTaskCommand.positionList`，明确不以 `roadYaw` 补全 yaw。
- `storage.py`：版本化 JSON、服务器/mapId 隔离、原子替换、备份和导入校验。
- `canvas.py`：米制 QGraphicsView、路径/车体/车道绘制、方向变换、鼠标编辑和撤销栈。
- `control_panel.py`：图层开关、车道属性、锚点/圆弧/贝塞尔数值编辑、通行结果和四角半径明细。
- `main_window.py`：层级导航、后台查询、车道上下文切换、脏状态协议和后台分析。
- `logging_setup.py`：UTF-8 JSON 事件、关联 ID、每日/容量混合轮转、保留策略和非阻断故障恢复。
- `workers.py`：线程池适配器，只向 UI 传递简短可恢复错误；完整异常堆栈写入本地日志。

## 坐标变换

领域和存储始终使用后端原始坐标 `(x, y)`。显示方向 `θ` 仅在画布边界应用：

```text
x_display = x·cos(θ) - y·sin(θ)
y_display = x·sin(θ) + y·cos(θ)
```

鼠标编辑先用逆旋转还原原始坐标再写入模型。因此改变地图方向不会改写路径或车道 JSON。

## 车辆包络

路径点为前轴中心。车辆局部顶点为：

```text
(+中心前距, ±车宽/2)
(-中心后距, ±车宽/2)
```

顶点按 yaw 绕前轴中心旋转和平移。缺 yaw 不构造矩形。

## 车道区域

- 每段中心线独立产生半径为“总宽/2”的平头缓冲。
- 真实圆弧以圆心和顺/逆时针方向存储，按弦误差容差离散；不是车道边界圆角的替代名称。
- 三次贝塞尔按容差自适应离散。
- 内部锚点按车道默认或锚点覆盖加入圆角/尖角连接区域。
- GEOS miter limit 截平过长尖角。
- 开放首尾不加端帽；闭合车道所有锚点均作为连接点。
- 所有启用车道区域使用并集，通行判断不绑定某一条路径或车道。

车道 schema 2 在线段中增加 `arcCenter` 和 `clockwise`。schema 1 仍可读；只有操作者手动保存时才先生成 `.bak` 并写成 schema 2，导出始终为 schema 2。

## 自动车道生成

- 连续重复 `(x, y)` 先去除，yaw 不参与生成。
- 最大拟合偏差统一约束预简化、圆弧拟合和最终来源点到中心线的距离。
- 圆弧用来源采样拟合并检查旋转方向及两端切向；失败回退尖角且进入预览统计。密集路径先按偏差预简化，单个圆弧拟合窗口最多 64 个简化点，长圆弧可拆为相邻同半径段。
- 贝塞尔在每个来源区间使用三次曲线，相邻段共享切线方向；来源点均为锚点，因此偏差约束不会被跨样本的单曲线近似破坏。
- 预览不进入 `LaneLayout`；确认时深拷贝整条车道并推入一个 `QUndoCommand`。

车道中心线长度不依赖绘制离散容差：直线为欧氏长度，圆弧为 `半径 × |扫角|`，三次贝塞尔对速度函数自适应积分。设置总长时，以所有真实线段解析包围盒的中心为缩放中心，对锚点、贝塞尔控制点和圆弧圆心施加同一比例；宽度保持不变。

## 整弯转弯半径

- yaw 通过最短角差连续累计；转弯阈值严格比较，缺 yaw 将路径切成独立有效块。
- 每条测量由入弯/出弯端点索引定义。端点位置和区间累计 yaw 解出一个等效旋转中心；中间样本只负责展开 yaw 环绕和保留真实旋转圈数。
- 等效圆心相对入弯车辆航向的叉积决定车体左/右侧；前轴中心及入弯车辆四角到同一圆心的距离形成五个固定半径。
- 自动识别在线程池中执行并带独立代次；路径变化、阈值变化、上下文切换或删除测量会使迟到结果失效。计算完成后只在 UI 线程原子替换自动组。
- 测量状态只保存名称、来源、端点和单调计数器，车辆尺寸变化时按端点重新计算派生半径。路径 SHA-256 指纹覆盖完整有序 `(x, y, yaw)`，不匹配时返回空状态。

## 连续扫掠近似

每对 yaw 完整的相邻路径点按如下样本段数插值：

```text
max(ceil(位置距离 / 位置步长), ceil(|最短 yaw 差| / yaw 步长), 1)
```

每个姿态检查 `traversable_area.covers(vehicle_polygon)`。完全覆盖时净距为车体边界到区域边界的最小距离；不覆盖时报告负值并记录越界。缺 yaw 点及其相邻段跳过并标记数据不完整。

这是可配置分辨率的数值近似，不是解析连续碰撞证明。

## 并发模型

- HTTP 查询使用 2 线程 Qt 线程池。
- 几何分析使用独立单线程池，避免多次修改同时占用 CPU。
- 通行分析使用单线程几何池；自动转弯识别使用独立单线程半径池。两者各自带代数编号，过期结果不覆盖新状态。
- UI 和 QGraphicsScene 只在主线程修改。

## 数据一致性

- 配置和车道先写同目录临时文件，再用 `os.replace` 原子替换。
- 覆盖保存前复制 `.bak`。
- 车道上下文键为规范化 API 根地址 SHA-256 前 16 位加 mapId。
- 转弯半径测量按服务器、租户、订单、任务、命令和路径类型隔离，保存在 `data/turn-radius-measurements.json`；用户名、密码和令牌不参与键生成。
- 导入文件必须声明 schema 1 或 2、米和弧度；导入布局只整体替换，不合并。

## 日志与故障边界

- 源码和冻结构建均通过 `data/` 的同级目录解析 `log/`，不把日志放入车道数据树。
- 每条 JSON 日志包含本地时区时间、级别、稳定事件名、logger 和关联 ID；INFO 用于生命周期和业务摘要，DEBUG 按 ADR 0004 保留完整未脱敏诊断字段。
- 写入失败只改变 `LoggingState`，不向业务调用抛出；每个后续事件重新尝试打开文件，状态通过 Qt 信号更新主线程状态栏。
- 主线程未捕获异常、后台工作器异常和分析异常记录完整堆栈，UI 只显示简短可恢复错误。
