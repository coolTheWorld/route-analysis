# 路径通行分析工具功能规格

状态：已确认
日期：2026-08-27

## 1. 产品范围

本工具供调度系统排障和车道宽度验证使用。它只读取既有调度数据，不修改订单、任务、命令、地图或车辆状态。操作者从订单逐级进入任务、命令，在同一画布比较下发路径和实际执行路径，并绘制独立于路径的车道区域来检查车辆在直行和转弯时是否可通过。

工具另含一个不连接任何数据源的场景速算页（第 8 节），仅凭车辆参数对典型路口和掉头工况做离线几何计算。它与前述分析互不共享路径。

## 2. 连接与认证

- API 根地址可配置，填写完整前缀，例如 `http://host/admin-api`。
- 租户名可配置，默认 `suntae`。
- 用户名和密码可配置。
- 客户端先查询租户 ID，再携带租户请求头登录。
- 令牌失效后自动重新登录一次并重放原只读请求；再次失败则提示用户。
- 所有值保存于本地配置。密码依照用户明确选择明文保存，不做额外加密。
- 日志不得记录密码、令牌、Authorization 请求头或完整配置对象。

## 3. 调度数据导航

- 订单列表由服务端分页，支持按一个订单 ID 精确查询。
- 通过双击、Enter 或明确的“进入”动作依次导航：订单 → 任务 → 命令 → 路径。
- 左侧始终显示当前层级和面包屑，并能返回上层。
- 单个命令加载下发路径与实际执行路径；两者的数据均直接取后端现有接口。

### 3.1 命令点位检查与地图联动

- 进入命令后，左侧保留命令表格，并在其下方以可拖动的上下分栏显示点位表格和 JSON 详情；离开命令层级时隐藏点位检查区域。
- 点位区域提供“下发点位”和“实际点位”两个标签，默认显示下发点位；两个标签分别记忆最后选中的点位，切换命令时清除旧选择。
- 点位表格按 `positionList` 原始顺序一次加载全部点位，使用按需渲染模型且不分页；列为“序号、X、Y、Yaw（rad）、Gear”，界面序号从 1 开始，并支持按该序号跳转。
- `Gear` 原样显示后端值。字段缺失或无效时对应单元格显示“—”；无效点仍保留在表格并可查看原始 JSON，行上显示数据异常标记。无效 `x`/`y` 不参与地图绘制或定位，无效或缺失 yaw 只绘制中心点。
- JSON 区域提供“命令 JSON”和“点位 JSON”标签。命令 JSON 显示当前下发/实际来源的 `commandStr`（或等价业务字段）解析后的完整对象，不显示接口响应包装；点位 JSON 显示当前选中点位的完整原始对象。两者均只读、格式化并支持选择、复制和滚动。
- 选择点位表格行时，画布以独立图层高亮对应中心点和当前车辆参数计算的车辆矩形；普通中心线或车辆图层关闭时，高亮仍显示。车辆或地图参数变化时普通与高亮车辆同步重算。
- 选中点位在当前视口外时，画布自动平移使其居中但不改变缩放比例；已在视口内时不移动。
- 点击画布当前点位标签对应路径的中心线样本时，反向选择并滚动到左侧表格行，同时显示点位 JSON。重合或过近样本在同一位置连续点击时按来源顺序循环选择；非当前标签对应路径不参与命中。
- 下发路径与实际执行路径独立加载并独立显示错误；一侧失败不清空另一侧已成功数据，失败标签提供重试。实际路径为空时明确显示“无实际路径数据”。

## 4. 坐标、车辆和地图方向

- 后端路径点 `(x, y)` 表示叉车前轴中心，单位为米。
- yaw 单位为弧度；原始坐标系 `yaw=0` 指向正 X（东）。
- 车辆为矩形：车宽、中心前距和中心后距均可输入且必须大于零，车长为前距与后距之和。
- 前轴中心到车头沿正 yaw 方向延伸中心前距，到车尾沿反方向延伸中心后距。
- 全局默认车辆参数可配置；可按 VIN 保存覆盖参数。
- 每个带 yaw 的原始路径点均绘制车辆矩形；缺失 yaw 时只绘制中心点，不推断朝向。
- 地图方向是弧度输入，默认 0；它旋转路径、车辆和车道的显示，不改写任何原始数据。

## 5. 路径显示

- 下发路径和实际路径默认同时可见，颜色和图例清晰区分。
- 两类路径分别提供中心线、车辆矩形和异常结果开关。车辆矩形一项为四态：整车、仅前段、仅后段、关，两类路径各自独立。
- 仅前段只绘制前轴中心点到车头那一段矩形，仅后段只绘制前轴中心点到车尾那一段，分界边落在前轴中心点上。这只影响绘制：越界判定、最小净距和通行余量分析永远使用完整车辆包络，通行余量视图与导出报告中的车辆图形也不随该选择改变。
- 关闭车辆矩形不清除已选择的分段；重新打开时回到关闭前看的那一段。
- 中心线图层同时绘制折线和圆点标记，且每个具有有效坐标的位姿点恒定对应一个圆点，任何缩放下都不按密度丢弃标记；视口之外的圆点只是不绘制，不计为丢弃。
- 圆点直径以屏幕像素计量，不随缩放线性变化：稀疏处取基准直径，拥挤处按相邻两点中较小的屏幕间距成比例收缩，并有正的最小直径下限，因此密集路径缩小时圆点变小而不会连成实心带，放大后重新展开为可分辨的标记。
- 缺少 yaw 的位姿点在中心线图层中绘制为空心圆点，关闭车辆矩形图层时仍可辨认；空心圆点与普通圆点使用同一套收缩规则，因此密集处需要放大才能分辨。非当前点位标签对应路径的圆点绘制为更小的半透明空心圆，表示该路径不参与命中。
- 无有效 `x`/`y` 的 `positionList` 条目没有坐标，因此没有对应圆点；坐标完全重合的样本各自绘制，但在屏幕上仍然重叠为一个标记，按既有规则通过在同一位置连续点击循环选择区分。
- 支持一键只查看下发路径或只查看实际路径，以及恢复全部显示。
- 画布保持 X/Y 等比例米制缩放，显示网格、坐标轴和鼠标原始坐标。

## 6. 车道建模与编辑

- 车道是独立绘制的道路几何，不与任一条路径绑定。
- 启动手绘后，首次点击前显示实时吸附的候选锚点；第一次点击固定起点后，中心线与按当前总宽生成的半透明车道区域跟随鼠标移动，下一次点击固定同一吸附位置并继续下一段。
- 鼠标依次添加多个锚点形成中心线；每段可选择直线、真实圆弧或三次贝塞尔曲线，贝塞尔具有两个可编辑控制点。
- 手绘草稿使用区别于正式车道的绿色样式；鼠标移出画布时隐藏候选锚点和动态末段，保留已固定几何，返回后恢复动态预览。
- 相邻固定锚点不得重合；至少具有两个有效锚点后，才可通过完成按钮、`Enter` 或双击完成。双击不产生重复锚点，`Backspace` 撤销最后一个锚点，`Esc` 取消整条草稿。
- 车道可为开放路径或闭合环；开放车道端部为平头。
- 车道宽度表示以中心线为中心的整个可通行宽度，每条车道可单独设置；新车道使用全局默认宽度，绘制中修改总宽必须实时更新草稿预览。
- 每条车道拥有默认连接样式；新建车道默认为尖角。每个锚点可覆盖为圆角或尖角。
- 尖角连接应用 miter 长度上限，超过上限时截平，避免产生无界尖刺。
- 支持锚点和控制点拖动，也支持数值输入原始 x/y 坐标。
- 支持吸附到当前可见路径点；经显示旋转后编辑的坐标必须逆变换为原始坐标保存。
- 支持车道启用/禁用、重命名和删除。
- 禁用车道仍然显示并允许选择、整车道拖动及修改长度和宽度；禁用仅表示不参与可通行区域并集与越界分析，不表示锁定编辑。
- 整车道拖动、长度显示、长度输入和宽度输入统一适用于自动生成、手绘及导入的所有本地车道，不为自动生成车道保留专用来源类型。
- 车道长度定义为中心线各直线距离、真实圆弧弧长和贝塞尔曲线弧长之和；闭合车道包含首尾闭合线段，车道总宽及开放端部不计入长度。
- 输入目标长度时，以完整中心线实际边界框中心为不动点，将全部锚点、贝塞尔控制点和圆弧圆心按同一比例缩放，使中心线总长度达到目标值；缩放保持原形状比例且不改变车道总宽。
- 在锚点或贝塞尔控制点上按下左键后未发生拖动即释放时，若同一位置存在当前点位标签对应路径的样本，则选中该样本；控制点命中不再吞掉该次点击。发生拖动时只移动控制点，不选中样本。
- 左键拖动锚点或贝塞尔控制点时仅移动该控制点；左键拖动车道中心线或车道填充区域的非控制点位置时平移整条车道；左键拖动画布空白处时平移画布。一次连续整车道拖动只产生一个撤销/重做步骤。
- 多条车道在鼠标位置重叠时，锚点或贝塞尔控制点命中优先于整车道命中；当前已选车道覆盖该位置时优先命中当前车道，否则命中绘制层级最上方的车道。
- 从未选中的车道开始整车道拖动时，鼠标按下即将该车道设为当前选中车道并同步右侧名称、长度、宽度及几何参数，然后进入拖动。
- 整车道拖动遵循现有路径吸附开关：关闭时自由平移；开启时将鼠标按下时抓取的车道位置吸附到最近的可见路径点，并把同一位移应用于全部车道几何。
- 已固化车道的长度和总宽输入均以米为单位且必须大于零；输入过程中不连续修改几何，按 `Enter` 或失去焦点时一次性提交，每次有效提交各产生一个撤销/重做步骤，无效输入恢复原值并显示原因。手绘草稿的总宽是例外，输入时仅实时更新未固化预览，不产生撤销步骤。
- 整车道拖动、长度修改和宽度修改均沿用现有显式保存机制：操作后只修改内存布局并将窗口标为未保存，点击“保存”时统一写入本地车道文件；切换地图、导入或退出时继续使用现有保存、放弃、取消提示。
- 当导入或编辑形成中心线总长度为 `0 m` 的退化车道时，长度显示为 `0.000 m`，长度缩放不可用并提示“零长度车道无法按比例缩放”；锚点拖动、整车道拖动及宽度修改仍可用，锚点拉开使总长度恢复为正数后长度输入自动恢复可用。
- 自动生成车道以当前路径上用户选定的两个点位为范围。点击“按路径生成”后画布进入选点模式，逐个确认两个点位；不提供整条路径一次生成，需要整条时选首尾两个样本。
- 选点复用与手动半径测量相同的规则：每次点击都弹出端点候选列表由用户确认，序号从 1 开始与点位表格一致，`Esc` 或再次点击按钮退出。选点作用于当前点位标签对应的路径，来源因此由上下文确定，对话框不再提供来源下拉。
- 选点模式与手动半径测量的选点模式互斥，进入其中一个自动退出另一个：同一块画布上一次点击只能有一种含义。
- 两个点位必须是不同样本且都具有 yaw；缺少 yaw 时拒绝并说明原因，因为算不出该点位的车体范围。两点顺序颠倒时按样本序号升序规范化。两点之间的中间样本缺少 yaw 不影响生成，中心线只使用坐标。
- 连接方式可选沿原路径或直线。沿原路径取两点之间的原始位姿子序列，保留中间形状；直线连接忽略中间形状，此时弯道生成模式、最大拟合偏差和闭合车道禁用并说明原因，不静默忽略。直线连接下两点坐标重合时拒绝生成。
- 生成的车道两端各按该点位的车体外伸量延伸，使两个点位的车辆包络在长度方向上都落在车道内。外伸量取该点位车辆包络四角在该端走向线方向上的最大投影，走向线方向与位姿航向一致时等于中心前距或中心后距。
- 车道总宽不因车辆宽度自动调整；总宽小于车宽时对话框给出提示，说明两端车体会露出车道，但仍允许生成。
- 生成结果是与来源路径解除动态绑定的普通可编辑车道。
- 自动生成始终新增一条车道，不覆盖也不合并当前地图的既有车道；默认名称标明两个点位的序号范围。
- 自动生成时为整条车道选择统一的默认弯道模式；生成完成后仍可逐锚点调整尖角/圆角连接，并可逐线段切换直线/贝塞尔及编辑控制点。
- 圆角弯道必须在中心线中插入与前后直线相切的真实圆弧，不得只对车道区域边界倒圆；中心线模型因此支持直线、圆弧和三次贝塞尔三类线段。
- 圆弧弯道的半径由来源路径坐标样本自动拟合，生成后可查看并逐弯道手动修改；样本不足或无法稳定拟合时必须标记原因并退回尖角，不得静默猜测半径。
- 手动修改圆弧半径时保持前后直线方向及理论交点不变，并重算两侧切点和圆心；若切点会超出相邻直线可用长度，则拒绝修改并显示最大允许半径，不自动截断其他线段。
- 贝塞尔模式使用多段三次贝塞尔曲线拟合来源坐标，相邻曲线保持切向连续；每个来源区间一条三次曲线、来源点均为锚点，因此偏差约束不会被跨样本的单曲线近似破坏。
- 自动生成对话框提供单位为米的最大拟合偏差，默认 `0.05 m`；该值统一约束坐标简化、圆弧拟合和贝塞尔拟合。
- 自动生成车道默认带入全局“新车道默认总宽”，允许在本次生成时临时修改；生成后仍可按普通车道编辑宽度，不根据车辆尺寸自动推算道路宽度或安全余量。
- 自动生成默认创建开放车道，并在对话框提供“闭合车道”选项；来源路径首尾距离不大于最大拟合偏差时可自动勾选，但必须由用户最终确认。
- 自动生成中心线仅依赖有序 `(x, y)` 坐标，不要求路径点具有 yaw；连续重复坐标先去重，yaw 仅用于车辆姿态与转弯半径分析。
- 自动生成先以半透明车道区域预览，并显示两端延伸量、拟合偏差、锚点数、线段数及圆弧拟合失败回退计数；用户确认后才新增车道，并作为一次完整操作进入撤销栈，取消不修改当前布局。
- 确认或取消后停留在选点模式并回到等待第一个点位的状态，可连续生成多条车道；点击“结束选点”或按 `Esc` 才退出。

## 7. 通行分析

- 所有启用车道的区域取并集作为可通行区域。
- 对相邻路径点按位置和 yaw 同时插值，默认最大位置步长 0.05 m、最大 yaw 步长 0.02 rad；yaw 使用最短角插值。
- 插值路径上的每个有效姿态均生成车辆矩形并检查是否完全位于可通行并集内。
- 缺失 yaw 的原始点和它两侧相邻路径段不参与矩形分析，结果标记为数据不完整。
- 下发路径和实际路径独立分析并展示：
  - 绿色：车辆完全在区域内且最小净距不小于阈值；
  - 黄色：车辆在区域内但最小净距小于阈值，边界接触也属黄色；
  - 红色：车辆有任意部分越出区域。
- 默认净距阈值为 0.15 m，可配置。
- 每类路径结果显示最小净距及位置、首个越界位置、越界样本数、有效/跳过样本数和使用的分析步长。
- “连续”指按上述可配置步长做扫掠采样近似；界面和文档不得将其描述为解析几何的绝对证明。

### 转弯半径分析

- 前轴中心转弯半径及四角转弯半径直接使用下发路径或实际执行路径中的车辆位姿 `(x, y, yaw)` 计算，两类路径分别输出结果。
- 转弯半径不从自动生成的车道中心线反推车辆姿态；车道仅用于将车辆扫掠范围与可通行空间叠加对照。
- 系统不自动识别转弯，也不批量生成半径结果；全部转弯半径测量都由用户点击“计算转弯半径”后逐条选点建立。
- 下发路径与实际路径各自拥有独立的“计算转弯半径”入口、结果列表和默认名称序列；一次操作只处理所在区域对应的路径，不提供同时计算两类路径的总入口。
- 每类路径的结果列表按创建时间平铺展示全部测量，不分组；每条显示自定义名称并支持选择、重命名和删除。
- 测量只能从当前下发路径或实际路径已有的坐标点中先选入弯点、再选其后的出弯点；进入选点模式本身不在画布上添加任何标记。
- 选点模式下每次在路径上点击都弹出端点候选列表，由用户从列表中确认端点；不存在点击直接定端点的路径。点击未命中任何样本时不弹出列表，也不改变当前选择。
- 端点候选由离点击位置最近的样本及其前后各两个可绘制样本，与本次点击命中的其余样本合并去重后按路径顺序排列；离点击位置最近的那一项加粗标出。路径首尾附近邻居不足时集合相应变短，不向另一侧补齐。
- 关闭候选列表而不选择任何一项时不改变当前选择，也不创建测量。
- 画布只对已确认的转弯端点着重标记并标注序号，端点候选中的其余样本保持普通路径点外观；已选定的入弯端点标记保持到用户开始选择下一条测量的入弯点或退出选点模式才清除，因此选定出弯端点后两个端点同时着重标记。
- 转弯端点以其在来源路径中的样本序号作为身份；坐标相同但序号或 yaw 不同的样本仍是不同端点。手动重复检测和自动重算匹配均使用“入弯样本序号 + 出弯样本序号”，界面端点信息同时显示样本序号。
- 端点候选列表逐项显示样本序号、坐标和 yaw；序号与左侧点位表格一致，从 1 开始计数。坐标完全重合的样本因此始终可以逐个分辨和选择，路径折返回到同一坐标时也不例外。
- 两个端点可以跨越多个弯道或中间的反向转弯，不要求位于同一段连续转弯内；只要两个端点能够形成有限整弯等效旋转中心就计算。
- 选点模式完成一条有效测量后保持开启，并自动回到等待下一条入弯点的状态；用户点击“结束选择端点”或按 `Esc` 才退出，退出时丢弃仅选择了一个端点的未完成测量。
- 同一路径内不允许两条测量使用完全相同的入弯、出弯端点对；用户重复选择时定位并高亮已有测量，不创建新结果。
- 每条转弯半径测量使用入弯、出弯两个位置及两端之间路径样本连续展开后的累计 yaw 旋转量求一个整弯等效旋转中心，再计算该中心到入弯前轴中心点的固定距离，以及到入弯车辆前外角、后外角、前内角、后内角的四个固定距离；中间样本只用于消除 `±π` 环绕并确定真实转向和圈数，不生成局部半径样本、距离窗口、最小值、中位数或最大值统计。
- 每条测量均可单独删除。
- 测量具有可编辑的非空名称，默认使用“手动半径 N”；名称在同一类路径内必须唯一，重名时拒绝提交并提示，删除后名称可再次使用。删除测量后不重新编号或改写其他已有名称。
- 默认名称序号只递增；删除测量后不复用已经分配过的数字后缀。
- 读取本地测量文件时丢弃早期版本写入的自动半径记录，只保留用户选点建立的测量；文件不再写入自动测量的计数字段。
- 测量仅保存在本地，不上传后端；切换页面或重启后恢复。结果有效性由来源路径按顺序排列的全部 `(x, y, yaw)` 样本决定：点数、顺序或任一样本值变化时清除该路径的全部测量，仅命令状态、时间等非路径字段变化时保留，刷新后路径数据完全相同时继续恢复。
- 本地测量按“后端地址 + 租户 + 订单 ID + 任务 ID + 命令 ID + 路径类型（下发/实际）”隔离；用户名、密码或令牌变化不创建新的测量范围。
- 界面使用“前轴中心转弯半径、前外角半径、后外角半径、前内角半径、后内角半径”五个名称，不显示“车辆坐标半径”“中心点半径”或“前距外切”等旧称。
- 左右转按整弯等效旋转中心位于入弯车体航向的左侧或右侧定义，与车辆前进或倒车无关；界面显示“车体左侧转弯”或“车体右侧转弯”。
- 不提供转弯识别阈值设置；本地配置文件中早期版本写入的该字段被忽略。
- yaw 变化先用最短角规则连续展开以跨越 `-π/π`；不增加独立抖动容差。
- 测量的入弯点到出弯点之间只要存在任一缺失 yaw 的样本，就拒绝创建并显示缺失样本序号；不退回端点最短角差，也不从坐标方向推算 yaw。
- 每条测量直接显示转弯端点、转向、前轴中心转弯半径以及前外角、后外角、前内角和后内角四个整弯半径，不再显示局部统计或最大值发生位置。
- 入弯或出弯位姿缺少 yaw、两端不能形成有限整弯等效旋转中心或四角半径非有限时，不设置人为半径上限，提示原因且不新增结果，允许用户重新选点；已存在的测量在重算后无法得到有限半径时保留并标记“无法计算”及具体原因，避免静默漏项。
- 累计绝对 yaw 变化严格大于 `0.75π rad`（约 `2.356194 rad`）时按调度规则标记为“车体左侧掉头”或“车体右侧掉头”；掉头仍使用相同的四角半径算法。
- 转弯半径使用默认关闭的独立画布图层。选择一条测量时自动定位并高亮入弯到出弯之间的路径，同时显示入弯与出弯车辆矩形、共同的整弯等效旋转中心、从圆心到入弯前轴中心点及车辆四角的五条半径线、前轴中心及四个角从入弯到出弯的五条圆弧轨迹和数值标签；前轴中心使用与四角区分的颜色。
- 四角半径使用与车辆包络分析相同的尺寸选择规则：当前命令存在 VIN 专属配置时优先使用，否则使用全局车宽、中心前距和中心后距；结果面板显示本次尺寸来源。
- 本地测量以名称和转弯端点为稳定输入；全局车辆尺寸或当前 VIN 专属尺寸变化时，自动刷新所有已有测量的四角半径，名称与端点保持不变；前轴中心转弯半径不受车辆尺寸变化影响。

### 通行余量分析

- 通行余量是主窗口画布区的第二个标签页，与“地图”并列；左侧导航栏和右侧控制面板不变。
- 只分析当前命令的下发路径。实际执行路径不参与通行余量分析。
- 求解代价远高于其后的净距判定，因此只在该标签页可见时求解；标签页隐藏时只把结果标记为过期，切换到该页才真正计算。
- 路径按转弯区间识别切分为直行段与转弯段，转弯段收紧到实际改变航向的样本，使两个反向转弯之间的直行段仍是直行段。该切分只服务于本视图，不产生转弯半径测量、不写入本地测量文件、不在画布上标注转弯端点。
- 区段名称由点位序号区间和覆盖该段中点的启用车道名组成，序号与左侧点位表格一致、从 1 开始；不落在任何启用车道内时省略车道名。
- 净距剖面与可行偏置带上下并排，共用同一条横轴刻度和同一组区段分隔线；最紧的两处瓶颈用竖线贯通上下两栏。
- 偏置定义为把一个区段的全部位姿沿行进方向的法向整体平移，正值指向行进方向左侧。偏置不写回下发路径，也不修改车道。
- 逐段求解可行偏置带：先在搜索范围内粗扫求最优偏置，再向两侧二分求出使该段最小净距等于阈值的边界。最优偏置本身达不到阈值时该段没有可行偏置带。
- 相邻两个转弯之间的连接段只有一个偏置值，因此该段的可行区间取自身与前后两个转弯要求的交集。交集为空时报告耦合冲突并给出差值；本版不求所需的半径调整量。
- 瓶颈排行榜按最小净距升序展示每个区段的最低点，列出约束部位、回到可行带所需的最小偏置和路径进度。约束部位在车辆完全位于通行区域内时取离边界最近的角，越界时取伸出最深的角；无法区分单个角时记为车身侧边。
- 选中一行时在其下方展开该处的三区标尺：不可行、需路径偏置、居中即可通过。两个分界点由改写该段覆盖车道的总宽、重建通行区域后重跑扫掠判定链路二分求得，不使用闭式公式；该段不在任何启用车道内时不给出标尺。
- 选中瓶颈行只在地图中定位到该位姿并在状态栏提示，不切换标签页：该行的产出就是它下方刚展开的三区标尺，切走会把它毁掉。
- 点击主图任意处切回“地图”标签页并定位到对应位姿。主图点击本身没有就地产出，定位就是它的全部目的，因此它是唯一改变标签页的手势；图上方的说明文字写明这一点。
- 优化建议固定三张卡：首选、次选和不建议。所有建议卡带“只建议 · 不修改”标签；本功能不提供任何一键应用。
- 转角求解是通行余量页内的二级视图。入口是瓶颈排行榜标题栏的“进入转角求解”按钮，选中转弯行时可用、选中直行段时禁用；双击已选中的转弯行是等效的快捷方式。
- 选中一行会在其下方插入标尺行，只增删这一行，不重建整张表：重建会销毁其余行的表项，正在进行的点击手势随之失效。
- 转角求解把该转弯区段拟合成直线—圆弧—直线参数化形式，三个自由度作用在这套参数上再重新生成位姿，走与主视图相同的净距判定链路。拟合残差随结果显示。
- 三个自由度为入弯段偏置、出弯段偏置和起弯点。两条腿的偏置定下后，切于两腿且转角固定的圆弧只剩一个参数族，起弯点选的正是族中的哪一条；因此路径转弯半径是这三个自由度的因变量，推迟起弯收紧半径，提前起弯放大半径。
- 车道倒角半径读自该转角所在车道的圆弧段；车道在该处为尖角时输入框留空并提示，用户填入的值只用于本次求解，不回写车道。
- 车道倒角半径与路径转弯半径不等时给出偏置沿弯变化曲线：横轴为弯内弧长，纵轴为两条中心线的横向间距，形状为零到峰值再回到零的拱形。峰值为 `|R_lane − R_path| · (1/cos(Δ/2) − 1)`，两条弧的切点在直线上相距 `|R_lane − R_path| · tan(Δ/2)`，其中 `Δ` 为转角的累计 yaw 变化。曲线同时标出常数偏置近似在弯心处高估的余量。
- 转角俯视图必须把车道走向线和下发路径分开画，两条线不重合正是该视图存在的理由。
- 转角求解分别按两个自由度和三个自由度各求一次，并给出第三个自由度带来的净距增益。
- 视图明确列出未覆盖项：回旋线等变半径过渡、多段倒角或不规则墙面、相邻转角过近的深度耦合、拟合转角与原始离散路径的残差，以及区段连接处偏置突变未建模。
- 通行余量的全部结果都是当次会话的派生结果，不写入本地存储；偏置解、可行带、车道选择和倒角半径输入在切换命令或重启后不保留。

## 8. 场景速算

- 场景速算是主窗口画布区的第三个标签页，与“地图”“通行余量”并列。
- 整页离线：不连接调度后端、不发起网络请求、不读写 `data/`，主窗口没有选中命令时也必须可用。全部结果为当次会话的派生结果，切换标签或重启后不保留。
- 车辆参数默认取 `config.json` 的车辆尺寸与净距阈值；页内改动只留在内存，不写回配置。转弯半径不在配置中，默认 `1.20 m`，是经验值而非车型标称值，界面须注明按车型核实。
- 布局为左栏参数、中栏俯视图、右栏结果三栏。

### 8.1 变体

- 四个场景：直角转弯、直角 R 档直行转 D 档、直角 R 档转弯转 D 档、U 型转弯。
- 每个场景可选单向或双向、可选两种计算方向之一：道路中心线或帕累托极限；直角转弯与 U 型转弯另可选 D 档或 R 档，两个复合场景固定 R 档转 D 档，档位控件禁用并显示固定胶囊。合计 24 个变体（12 个布局 × 2 种计算方向）。
- 档位是纯几何量，唯一含义是前后悬相对行进方向对调：行进方向前悬在 D 档取中心前距、R 档取中心后距。不含任何动力学。
- 双向指同一辆车在同一布局里向两个相反方向各做一次机动，判定取两个互为镜像机动中的最不利者；不是两辆车会车，也不建模错车间距。
- 计算方向决定车辆能否偏离道路中心线以及道路参数由谁作主，只有两个值。**道路中心线**：全部横向偏移固定为零，道路尺寸全部由求解器给出；左栏道路参数只列给定项（U 型的隔墙宽，后缀“（给定）”），不列偏移，U 型起弯点仍由求解器优化。**帕累托极限**：车辆可偏离中心线，左栏列出该场景全部道路尺寸与全部腿的路径偏移（含 U 型起弯点），除隔墙宽这类给定项与共用腿外，用户可固定其中任意一项，其余由求解器求极限（见 8.3）。两者都是纯几何约束，与载重、速度、路面无关。
- 此前“计算方向”（求极限 / 校核）与“工况”（可否偏离中心线）是两组控件，现合并为这一组：可偏离中心线与可固定参数总是一起出现，校核只是把参数全部固定的特例（见 8.4），分开摆放等于给同一件事开两个入口。

### 8.2 机动

- 直角转弯：自支路（进入道）起步、车头朝路口，直线 → 与两腿相切的四分之一圆弧 → 沿主路（驶出道）直线驶离。双向为 T 口，两条镜像机动都自共用的支路起步、各自驶出到主路西、东两侧；不得反过来自主路驶入支路 —— 那会让两条机动在共用的支路里迎头相对。
- 直角 R 档直行转 D 档：R 档沿倒车道直行穿过转出道并继续下探，再换 D 档以四分之一圆弧转出。双向为十字，向西与向东两条镜像机动。
- 直角 R 档转弯转 D 档：起点整车停在支路内较深处、车头朝向支路深处，R 档先沿支路倒车直行一段，再一段四分之一圆弧倒转至主路的一侧，车头与主路摆正后换 D 档沿主路直行离开；车辆不返回支路。支路内的直行段每个位姿的横向几何都与摆出起点相同，对净距与出弯主路深度没有影响，只为把起点画得离支路口远一些。支路自身沿伸出方向不设尽头：车辆只是停在其中，支路再深也不构成约束，因此不求解支路深度。
- 该场景另给出**出弯主路深度**：倒车摆出所占用的那一段主路，自支路开口的外侧壁沿主路量起。它由扫掠结果量得而非求解得出，因为主路两端都继续延伸、都不是墙，且双向布局里一条机动正是从另一条摆出的那一侧驶离，把它当成墙会挡住本该量的那次驶离。取值只在倒车位姿上量，最宽的一处正是车头与主路摆正的那一瞬。
- U 型转弯：上行直线 → 半圆 → 下行直线，半圆半径为两条巷道路径的间距之半，须不小于最小转弯半径；起弯点在两种计算方向下都是自由变量，帕累托极限下可被用户固定。双向为三巷两墙：两条机动都自中巷起步、各自驶入一条外巷，不得反过来自外巷起步驶回中巷 —— 那会让两条机动在共用的中巷里迎头相对。中巷被两个机动共用，其横向偏移固定为零，只有外巷偏移可动。
- 可通行区域多边形上纯为闭合而存在的端墙位于道路继续延伸的方向，须外推到任何位姿都够不着，不参与净距测量；俯视图另按取景范围裁剪。

### 8.3 求道路极限尺寸

- 结果是帕累托前沿上的一个点：每一项尺寸在其余项取当前值时都已不能再单独缩小。解不唯一，界面须写明这一点，不得表述为唯一最小值。
- 固定参数：帕累托极限下，用户改过的道路尺寸或路径偏移即视为固定，求解器不再改动它；取消固定即交回求解器。固定的按给定值参与求解，未固定的尺寸压到极限、未固定的偏移由求解器优化，两者的结果都回填到左栏输入框。道路中心线下没有固定参数，偏移一律为零。
- 双向布局里被两条镜像机动共用的腿（T 口支路、十字倒车道、借支路的支路、三巷的中巷）偏移恒为零且不可固定：两条机动互为镜像，任何非零偏移都只会让其中一条更紧，对称性已经替用户做了选择。该行照样列出，但置灰、显示 0。
- 偏移输入允许超出可行区间的值，结果直接报越界或不可行，不拦截：用户固定一个偏移正是为了看它能不能行，拦截会把答案藏起来。
- 全部待求尺寸都被固定时无可求解，结果为判定（通过 / 临界 / 越界），即 8.4 的校核。
- 切换场景、单/双向、档位或计算方向时释放全部固定：布局一变，固定的那个数就不再对应同一条腿。改车辆参数（转弯半径、车宽、中心前距、中心后距、净距阈值）保留固定，用户正是要看同一条固定的路换车之后还行不行。
- 求法为全部待求尺寸以同一步长一起收缩，直到每一项各自顶到自己的墙为止。不得逐项依次压缩：那样排在第一位的尺寸会在其余尺寸尚无约束力时吃掉全部预算，收敛到前沿的极端顶点。
- 可行性不保证随尺寸单调，因此每一步都须先判可行再落子，不得对任何一项直接二分。
- 任何一项尺寸都不得停在搜索上界。停在上界表示搜索没有找到答案，不表示道路真的需要那么宽，不得作为“已求解”呈现。
- 未固定任何横向偏移时，帕累托极限解出的每一项尺寸都不得大于同参数下道路中心线的对应项。帕累托极限只是多给自由度，中心线解在其下必然可行；解出更大的尺寸等于宣称允许偏离中心线反而要求更宽的路。实现上以中心线解逐项封住帕累托解的搜索上界，因此这时帕累托极限的产出是“在中心线方案之上偏移还能省多少”，而不是另换一条道路。被固定的尺寸与起弯点一并带进中心线求解，封顶仍以同一组固定项为前提。
- 有横向偏移被固定时不施加中心线封顶：车辆不再自由停在中心线上，“中心线解必然可行”这一封顶依据失效。被固定的偏移可能真的要求比中心线更宽的路，那是用户主动固定的后果，求解器不得把它压回中心线解。
- 无解时给出净距阈值需降到多少以下才有答案，不只报告失败；有固定项时瓶颈说明须写明无解是在当前固定的尺寸与偏移下得出的。状态卡此时提示放宽或取消部分固定，而不是阈值上限，因为无解多半来自固定值而非阈值。
- U 型只固定巷道宽时，半圆装不装得下在搜索前就能判定：按自由的巷道偏移贴到外侧墙的最大转弯半径判，装不下时给出的“巷道至少需多宽”也按此二分求得，不再是居中公式 `2R − 隔墙宽`。
- U 型巷道宽加隔墙宽装不下最小转弯半径时不绘制无法成立的圆弧，改为直接给出巷道至少需要多宽。

### 8.4 校核给定道路

- 不再提供独立的校核计算方向：在帕累托极限下把该场景全部尺寸固定即等价于校核给定道路，判定规则与既有越界分析同源，给出通过 / 临界 / 越界、最小净距、相对阈值的余量以及瓶颈位姿及其约束角位；判定为越界时不弹窗，只按状态色呈现。

### 8.5 俯视图

- 由 QPainter 自绘，等比缩放居中。图层自下而上为网格、可通行区域、道路中心线、车辆扫掠范围、路径、越界位姿、尺寸标注与瓶颈标记。
- 俯视图上不标注档位。档位是左栏的输入，在图上重复一遍只是占地方；路径本身仍以实线与虚线区分前进段与倒车段，图例说明其含义。
- 提供扫掠包络、尺寸标注、网格三个图层开关；图层开关只重绘，不触发重算。
- 扫掠包络可选整车、中心前距或中心后距。分界落在前轴中心点上，因此选中心前距画出的正是中心前距那一段、选中心后距画出的正是中心后距那一段。这只影响绘制，净距判定与求解结果永远使用完整车辆包络。该选择置于左栏车辆参数中、紧接中心前距与中心后距两项之下，并与这两项同名，不占用俯视图标题栏。地图页的同一分段沿用“仅前段 / 仅后段”，因为那里没有相邻的尺寸输入可指。
- 俯视图标题独占一行，图层开关与模拟运行另起一行。变体全名与这些控件并排时两者都会被截断，按钮会被省略号吞掉标题。
- 前段与后段各有一个固定颜色，不提供取色。两者与颜色的对应关系必须在图例中写明，否则固定配色无从分辨。
- 路径须画出行进方向标记以及起点与终点。方向按行进方向而非车头朝向绘制：倒车段两者相反，而路径要表达的是车体往哪边走。双向布局的两个机动各自标出起点与终点。
- 起点与终点只画圆点，不在图上加文字：标注贴在几像素宽的圆点旁会盖住圆点本身。哪个点是哪个由图例说明，因此图上凡是无文字的圆点，其颜色必须两两可分 —— 起点、终点与最小净距点各用一种颜色。
- 圆点在全部图层之上绘制。尺寸标注的文字底衬是不透明的，先画圆点会被后画的标注整块抹掉。
- 提供“模拟运行”：车体包络自起点沿路径走到终点，双向布局的两个机动同时走。回放只重画已经算好的位姿，不重新求解、不改变任何尺寸。跑完停在终点，中途再次点击或任何输入变化立即中止。
- 图例须覆盖可通行区域、扫掠前段、扫掠后段、D 档路径、R 档路径、行进方向、起点、终点、道路中心线、越界位姿和最小净距点，并在放不下时换行，不得截断丢项。

### 8.6 结果与交互

- 左栏道路参数每行一个输入框。帕累托极限下待求尺寸与非共用腿的偏移行右侧带一个可勾选的“固定”开关：改值自动勾上，取消勾选即交回求解器（勾选时冻结的是屏幕上正显示的值）；未固定行的值由求解结果回填，正在键入的行不被回填。给定项（隔墙宽）无开关；共用腿的偏移行置灰、显示 0，开关位置改为“共用”标记。点击已选中的计算方向、场景、通行方向或档位按钮不算切换，不释放固定。道路中心线下只列给定项，不带开关。
- 右栏给出求解状态或判定、道路尺寸（被固定的项标“（固定）”、给定项标“（给定）”）、路径偏移、四角转弯半径和一句话瓶颈说明。求解状态卡含最小净距与相对阈值余量；全部尺寸固定时该卡即为校核判定。
- 路径偏移卡在帕累托极限下列出全部非共用腿（共用腿恒为 0，只在左栏标出）：每条腿的偏移值、被固定的标“（固定）”、各自的可行区间，并在说明文字里给出“全部偏移归零时最小净距”作为对照，让用户看出偏移换来了多少余量。
- 四角转弯半径使用闭式精确公式，与既有转弯半径分析同名：前外角、后外角、前内角、后内角。
- 任何输入或分段切换后经防抖重算；重算在线程池执行并按代次丢弃过期结果，重算期间控件不禁用、只显示进行中提示。
- 转弯半径不大于半车宽加净距阈值时给出警示，此时内侧几何自相交。
- 右栏底部提供「导出 PDF 报告」：把当前变体导出为一页 A4 横向 PDF，与屏幕同源绘制。页眉带齐场景变体全名（含通行方向、档位与计算方向）、车辆参数、转弯半径、净距阈值与全部固定项及其值 —— 报告会离开这个工具，没有前提的图比没有图更危险；页脚为离线速算免责声明。正文为俯视图（沿用当前图层开关）与右栏全部结果卡。求解或校核有结果后按钮才可用。不提供 CSV 导出。

## 9. 本地持久化与导入导出

- 源码运行时数据目录为仓库 `data/`；打包运行时为 EXE 同级 `data/`。
- 文件布局：
  - `data/config.json`：连接、车辆默认值、分析参数和界面设置；
  - `data/vehicle-profiles.json`：VIN 车辆参数覆盖；
  - `data/lanes/<server-id>/<mapId>.json`：车道布局。
- `server-id` 从规范化 API 根地址稳定散列，避免路径非法字符和不同服务器冲突。
- 车道布局在命令和订单间按服务器与 mapId 复用。
- 车道只在用户点击保存时写入；修改后显示脏状态。
- 切换 mapId、切换服务器或退出时，对未保存修改提供保存、放弃和取消。
- 每次覆盖保存前保留上一版本备份。
- 导出为带版本、服务器标识、mapId 和单位信息的 JSON。
- 导入先预览并校验；服务器/mapId 不一致时明确警告。导入只替换当前布局、不合并，执行前确认并备份。
- 圆弧线段引入车道 schema 2；继续读取 schema 1 并仅在内存转换，不自动覆盖旧文件。用户下次手动保存时先备份再写为 schema 2，导出统一使用 schema 2。
- 添加、移动、删除、改宽度、改线型和改连接样式均支持撤销/重做。

### 本地日志

- 日志目录与 `data/` 同级：源码运行写入仓库 `log/`，打包运行写入 EXE 同级 `log/`。
- 默认日志级别为 `INFO`，设置中可切换 `DEBUG / INFO / WARNING / ERROR`；修改后立即生效并保存到本地配置。
- 当前文件名为 `route-analysis.log`，使用 UTF-8 和本机时区；每天零点或单文件达到 `20 MiB` 时轮转，以先发生者为准。始终只保留最近 30 个历史文件并自动删除更旧文件，最大磁盘占用约 `620 MiB`，DEBUG 高频时可能保留不足 30 天。
- `INFO` 记录应用启动/退出、版本、操作类型、成功/失败、耗时、数据数量，以及订单、任务、命令和 mapId。
- `DEBUG` 按用户确认记录未脱敏的全部接口参数、用户名、密码、令牌、Authorization/tenant 请求头、完整配置、响应正文、VIN、完整路径坐标、导入文件正文及几何分析细节；不得把 DEBUG 日志提交版本库或打入发布包。
- 应用不对 `log/` 增加 ACL、加密、脱敏或其他访问控制；该决定只适用于日志，不移除现有只读 API 边界和输入校验。
- `log/` 创建失败、文件占用或磁盘写入失败时不阻断业务功能；状态栏持续显示“日志不可用”，并在后续日志轮转时自动重试恢复。
- 捕获 GUI 主线程、后台网络任务和几何分析任务的未处理异常，以 `ERROR` 记录完整 Python 堆栈、线程名和当前操作上下文；界面仅显示简短错误提示，不生成 Windows 内存转储。
- “帮助”菜单提供“打开日志目录”和“打开当前日志”；只打开本地文件，不提供上传、发送或清空日志功能。

## 10. 首次运行与设置

- 首次运行必须填写有效的车宽、中心前距、中心后距和默认车道宽后才能进入主界面。
- 连接配置可随后修改；修改服务器时按脏状态规则处理当前车道。
- 地图方向、净距阈值、位置步长和 yaw 步长可配置，其中步长放在高级分析设置。
- 自动车道最大拟合偏差、上次弯道生成模式、上次两点连接方式和日志级别写入 `config.json`；不配置半径计算窗口，也不配置转弯识别阈值。
- 车辆分段显示不持久化，每次启动回到整车，与其他图层开关一致。
- 设置界面与当前配置模型移除旧版半径计算窗口；加载旧 `config.json` 时兼容并忽略遗留字段，下次保存时不再写回。
- 每次打开自动生成对话框时，来源重置为下发路径、宽度取全局默认车道宽，闭合状态按首尾距离重新判断；这些本次生成选择不沿用上次值。

## 11. 界面与可用性

- 单窗口布局：左侧分层数据导航，右侧大画布，设置与分析结果使用可折叠区域。
- 所有主要动作可通过键盘到达；图标按钮具有文本提示和可访问名称。
- 网络和较长分析在后台工作，主线程保持响应；提供明确的加载、空数据、错误和重试状态。
- 错误提示面向操作恢复，不暴露调用栈或敏感请求信息。
