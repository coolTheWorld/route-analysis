# Handoff: 场景速算标签页（离线极限工况计算）

## Overview

给 `route-analysis`（Suntae 路径通行分析）主窗口的画布标签区新增第三个标签页「**场景速算**」，位于「地图」「通行余量」之后。

回答的问题：**不连任何调度数据，只凭车辆参数，现场速算 8 种典型路口/掉头工况的道路极限尺寸。**

- **正向（求道路极限）**：输入 转弯半径 / 车宽 / 中心前距 / 中心后距 / 净距阈值 → 求出道路的极限参数（各道最小宽、倒车下探长度、支路深度、端头深度、所需路径偏移）。
- **反向（校核给定道路）**：再输入实际道路尺寸 → 判定 通过 / 临界 / 越界，给出最小净距、相对阈值余量、可行偏移区间与最优偏移。

场景 × 变体（对应需求方三张草图 `原始需求草图/1.png`–`3.png` 的 8 张小图）：

| 场景 | 单向 | 双向 | 档位 |
|---|---|---|---|
| 直角转弯（L / T 路口） | ✓ | ✓ | D / R 可选 |
| 直角R档直行转D档（倒车穿越再转出） | ✓ | ✓ | 固定 R→D |
| 直角R档转弯转D档（倒入支路再驶出 = 借支路掉头） | ✓ | ✓ | 固定 R→D |
| U型转弯（端头掉头） | ✓ | ✓ | D / R 可选 |

每个场景另有「车辆必须在道路中心线行驶 / 极限工况（可偏离中心线）」两种工况 —— 与草图中每张小图下的变体清单一一对应。

## 核心算法（实现的地基，先读这节）

### 车辆模型

坐标按叉车**前轴中心**解释（与全库一致）。车宽 `W`、中心前距 `Lf`、中心后距 `Lr`；转弯半径 `R` 为前轴中心圆弧半径（等效旋转中心在前轴线上、距车体中心线 `R`）。

四角半径（闭式，右栏「四角转弯半径」卡直接用）：

```
Ro = R + W/2,  Ri = R − W/2
前外角 = √(Ro² + Lf²)   后外角 = √(Ro² + Lr²)
前内角 = √(Ri² + Lf²)   后内角 = √(Ri² + Lr²)
```

### 档位的几何含义（关键，别做错）

D/R 档在同一条几何路径上的差别 = **车体前后悬相对行进方向对调**：

```
行进方向前悬 lead = (D档 ? Lf : Lr)
行进方向后悬 trail = (D档 ? Lr : Lf)
```

推论（原型已验证）：直角弯**驶离弧起点的那条腿**吃 trail 侧外摆（D档=后外角 √(Ro²+Lr²)），**弧终点的那条腿**吃 lead 侧外摆。所以 D 档进入侧要求更宽、R 档驶出侧要求更宽 —— 两档的宽度需求在两条腿之间对调。

### 净距引擎（与「通行余量」同思路，纯几何版）

1. 每个场景生成：**可通行区域多边形**（直角墙体，单环，含凹口）+ **位姿序列**（直线段按 0.05–0.06 m 步长、圆弧按 0.02–0.03 rad 步长采样；每个位姿带 lead/trail/档位）。
2. 每位姿车体矩形 vs 区域边界：矩形 4 边 × 多边形各边求**线段间最小距离**（相交=0）；4 角点做点在多边形内测试。全部在内 → 净距 = 最小边距；有角点在外 → 罚为负穿深。全程取最小值即**最小净距**，并记录最紧位姿与最近点对（图上红点）。
3. **正向求解**：对每个待求尺寸做**单调二分**（净距 = 阈值时的尺寸即极限值），多尺寸按 Gauss–Seidel 轮换 3 轮收敛（直角弯内角约束使两条腿耦合）；最后用细步长复核，不足则整体微加。**不要写闭式道宽公式**。
4. **偏移优化**（极限工况）：对各腿横向偏移做坐标下降（每变量 5–9 点扫描 × 2–3 轮、区间递缩）。U 型的**起弯点 yc 在任何工况下都是自由变量**，一并优化。
5. **双向** = 同一布局跑原机动 + 其**镜像机动**，取两者最小净距（对称化、按最不利取值；共享的中线偏移固定为 0）。

### 场景几何（区域 + 路径）

全部为直角墙体。以下坐标系 y 向上，弧均为四分之一圆（U 型为半圆）：

- **直角转弯**：单向 = L 角（横腿宽 wA + 竖腿宽 wB）；双向 = T 口（横向主路 + 竖向支路，跑西进/东进两条镜像弧）。路径：直线 → R 半径弧 → 直线；偏移 eA、eB 平移两段直线。
- **R档直行转D档**：竖向倒车道（宽 wV）穿过横向转出道（宽 wH），继续下探 **LS（求解量“长”）**；R 档直行倒过路口至前轴 y = 转出线 − R，换 D 档四分之一弧转出。双向 = 十字，向西/向东两条镜像弧。倒车下探的理论下界 ≈ `R + Lr + c − wH/2`（引擎会给出精确值）。
- **R档转弯转D档**：横向主路（宽 wH）+ 南向支路（宽 wV、深 LS）。机动 = 借支路掉头：D 档驶过支路口 → R 档四分之一弧倒入支路（弧心在支路线外侧 +R）→ D 档另一条四分之一弧（弧心在支路线另一侧 −R）驶出，出向与来向相反。两弧同切支路中线，横路上占用错开。
- **U型转弯**：两条巷道（宽 w）夹隔墙（宽 b），端头深 **D（求解量“长”）**。路径 = 上行直线 → **半圆，半径 rs = 巷道路径间距/2 = (w + b − e1 − e2)/2**，必须满足 `rs ≥ R`（可以比最小转弯半径大，不能小）→ 下行直线。起弯点 yc（相对隔墙顶，+ 为深入端头）为第三自由度。双向 = 三巷两墙（M 形），跑左/右两个镜像掉头，外巷偏移 eo 共用、中巷固定 0。

### 偏移符号约定（需求方给定）

**弯道内侧为正、外侧为负**（U+2212 负号显示）。左栏底部与「路径偏移」卡都要写明。双向共享一条腿时用文字注明方向（如「向支路侧为正」）。

## Interactions & Behavior

- 任何输入 / 分段切换 → 150 ms 防抖后重算（Qt 用 `QTimer.singleShot`，参照通行余量页 100 ms 惯例）；重算期间标题行显示小转圈「计算中…」，控件不禁用。
- 正向极限工况的多变量求解最重（原型 ≲ 0.5 s）；Qt 侧放 `QThreadPool` worker，带 generation 计数丢弃过期结果（参照 `main_window.py` 现有模式）。
- 图层开关只影响绘制，不触发重算。
- 场景/档位/工况切换即时生效并重绘标题、道路参数表单、结果卡结构。
- 直行转D、转弯转D 两场景档位控件禁用（固定 R→D）。
- 反向校核出「越界」时不弹窗，只按状态色呈现 —— 与全库「只建议 · 不修改」产品约束一致。
- 无任何持久化、无网络请求；不写 `data/`，不写日志以外的任何文件。

## State Management

- `mode`：`fwd`（求极限）| `chk`（校核）
- `scenario`：`corner` | `crossback` | `stubback` | `uturn`；`bidir: bool`；`gear: D|R`（复合场景忽略）；`extreme: bool`
- `vehicle`：R / W / Lf / Lr / threshold（默认取 `config.json`，本页内可临时改，不写回）
- `road_dims`：按场景 {wA,wB} / {wV,wH,LS} / {wH,wV,LS} / {w,b,D}
- `offsets`：各腿横向偏移 + U 型 `yc`；正向与极限工况下由求解器产出
- `result`：最小净距、判定、求解尺寸、最优偏移、可行区间、瓶颈（位姿 + 最近点对 + 角位名）
